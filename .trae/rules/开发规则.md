# 开发规则

## 0. 总纲

- `ref/` 只读参考：禁止在重构代码中 `import ref`、禁止运行时依赖 `ref/` 的任何文件
- 形态：FastAPI（后端）+ `web/`（静态前端）+ WebSocket（实时）+ pylsl（数据总线/进程间流转）
- 原则：高内聚、低耦合；入口层只做装配（wiring），不堆业务细节
- web前端不要把代码写在同一个文件中，需要分模块集成

## 1. 并发与性能

- 采集必须在独立 `multiprocessing.Process`（或等价后台线程）中运行，禁止阻塞 FastAPI 事件循环
- 事件循环内禁止阻塞 I/O 与长耗时 CPU：必须转移到进程/线程（例如 `asyncio.to_thread`）
- 高频 EEG 推送必须打包/节流：仅影响展示频率，不影响采集完整性；频率与窗口大小由配置控制

## 2. 配置与可扩展性

- 严禁硬编码：通道数（8/16）、采样率、设备名/地址/UUID、串口/蓝牙参数、LSL 流名、滑窗大小、刷新率
- 新增配置项必须在配置加载与校验层完成：默认值、范围校验、类型校验

## 3. 调试与日志

- 终端/日志：连接状态、异常堆栈、性能指标、资源占用
- 前端“调试输出”：只展示结构化调试事件 `{tag, message, data}`，禁止展示网络/BLE 连接信息
- 调试事件必须在采集侧产生，经进程间队列转发到主进程，再由 WebSocket 推送

## 4. 编码规范

- 核心函数/类必须有中文 Docstring（职责、参数、返回值、异常/边界条件）
- Python 函数必须有 Type Hints
- 依赖变更必须同步更新 `environment.yml`（包括 Python 版本与 pip 依赖版本）

## 5. 仓库洁净

- 禁止提交运行产物：`__pycache__/`、`*.pyc`、日志、抓包、导出的数据文件（除非明确要求）
