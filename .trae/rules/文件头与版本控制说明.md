所有新建的“源代码文件”（`.py/.js/.css/.html`）必须包含统一文件头，并按“文件级版本 + 上位机展示版本”管理（`__init__.py` 例外：不新增文件头）。

## 规则

- 作者：**仅新建文件时**填写“本机作者标识”（建议取自 `git config user.name` 或本机环境变量）；修改他人文件时**不要改原作者名字**
- 文件级版本：SemVer（`MAJOR.MINOR.PATCH`），每个文件独立控制；小改动优先升 `PATCH`
- 上位机展示版本：仅维护一个 SemVer（`MAJOR.MINOR.PATCH`），用于页面展示；每次提交前必须更新一次
- 修改日志：只记录关键/对外可见变更，按日期递增（同一天多次变更可合并）
- 文件功能：一句话说明“职责边界”，避免泛泛而谈

## 版本管理办法（强制）

### A. 文件级版本（每个文件独立）

- **适用范围**：所有 `.py/.js/.css/.html`
- **维护位置**：文件头 `版本:` 字段
- **升级规则（强制）**：
  - 只要发生修改且尚未提交：必须**升级文件头里的 `版本:`**（小改动优先升 `PATCH`），并在“修改日志”中**追加一行**。
  - **原作者修改**：修改日志版本号后**不加括号与名字**（例如：`1.0.1 修复某问题`）。
  - **非原作者修改**：只在修改日志的版本号后添加修改者信息（例如：`1.0.1 (Alice) 修复某问题`），**不要修改文件头里的原作者名字**。
  - 每次修改与提交只变动一个小版本号：优先升级 `PATCH`（例如 `1.0.1 -> 1.0.2`）
  - 需要提升 `MINOR/MAJOR` 时：仍遵循 SemVer 语义，但一次提交只允许推进一个版本号（避免跨级连跳）

### B. 上位机展示版本（每次提交前更新一次）

- **适用范围**：页面顶栏展示的版本号（对用户可见）
- **维护位置**：`configs/config.yaml -> app.ui_version`
- **升级规则**：每次提交前必须更新一次；小改动优先升 `PATCH`

## Python 文件头模板（Windows 环境可省略 shebang）

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Copyright (c) 2026 BUAA BHB. All rights reserved.

文件功能: {该文件的职责与边界，一句话}

修改日志:
- 2026-05-01: 1.0.0 创建文件
- 2026-05-02: 1.0.1 修复了XXX问题（原作者修改：版本号后不加名字）
- 2026-05-03: 1.0.2 (Alice) 修复了XXX问题（非原作者修改：仅在修改日志追加名字，不改原作者字段）

作者: {本机作者标识，例如 git config user.name}
版本: 1.0.0
"""
```
